# 如何使用本仓库

这套内容可以顺序阅读，也可以按问题进入。无论选择哪条路径，都建议把“读懂”变成可检查的动作：画一张图、复述一次消息流、在源码里定位一个类型，或写下仍然解释不清的问题。

## 路线一：第一次系统学习 Agent

适合：知道 ChatGPT，会一点编程，但对消息、上下文、工具调用还没有稳定认识。

推荐顺序：

1. 阅读[你将学到什么](01-what-you-will-learn.md)，先知道终点；
2. 阅读[从大模型到 Agent](../01-foundations/01-from-llm-to-agent.md)，把模型与宿主程序分开；
3. 再进入消息格式、工具调用、流式响应和最小循环；
4. 能独立画出循环后，再读 Pi 的包结构；
5. 最后进入 AgentSession、会话树、compaction 和完整运行追踪。

这条路线最重要的纪律是：**不要先跳到一张巨大的源码调用图。** 如果还分不清模型请求工具和程序执行工具，看见更多函数名只会制造“好像看懂了”的错觉。

## 路线二：已经调用过模型 API

适合：写过 OpenAI 或 Anthropic API 请求，熟悉 JSON 和流式响应，但没有系统阅读过 Agent 工程。

你可以快速略过模型基础，从 API 对比开始：

1. 对照不同厂商如何表示 system/user/assistant 内容；
2. 重点比较 tool definition、tool call、tool result 的对应关系；
3. 把自己写过的“收到 tool call 后执行函数”代码画成循环；
4. 再进入 `pi-ai`，观察 Pi 怎样把 provider 差异收敛到统一类型；
5. 顺着 `pi-agent-core` 查看这些统一消息如何参与 Agent Loop。

阅读时不要只问“字段名是什么”，还要问“这个字段由谁产生、由谁消费、能否被信任”。

## 路线三：已经使用或开发过 Agent

适合：理解 tool calling、memory、planning 等常见概念，希望直接学习 Pi 的工程取舍。

推荐从[源码地图](../../references/source-map.md)和完整运行追踪进入：

1. 先确定当前文章使用的[版本基线](../../references/version-baseline.md)；
2. 沿 `AgentSession → Agent/AgentHarness → runAgentLoop → pi-ai provider` 找主干；
3. 用事件和状态的变化验证自己对调用链的理解；
4. 遇到 `compaction`、steering、content block 等边界概念时，再回到基础章节；
5. 用其他框架的同类设计做比较，但避免只凭类名判断职责相同。

## 第一个 30 分钟

不要先安装很多工具，也不要急着读几千行源码。完成下面四件事：

1. 阅读 [Pi 官方 README](https://github.com/earendil-works/pi) 的包列表；
2. 在纸上或笔记中写下 `pi-ai`、`pi-agent-core`、`pi-coding-agent` 各自的一句话职责；
3. 阅读[从大模型到 Agent](../01-foundations/01-from-llm-to-agent.md)；
4. 用自己的话回答：**模型什么时候只是返回消息，程序什么时候真正执行动作？**

如果第 4 题答不清楚，重新看工具调用流程；如果能答清楚，你已经拥有进入 Agent 源码最重要的支点。

## 一次有效的章节阅读

不同章节不会使用统一模板，但你可以固定使用下面四个动作：

### 阅读前：写下预期

例如读 `agent-loop.ts` 前，先猜测它至少需要哪些输入、会产生哪些事件、怎样停止。预测不需要正确，它的价值是让你注意到自己的旧模型与源码证据之间的差异。

### 阅读中：区分四种陈述

- **源码事实**：可以在固定 commit 中直接找到；
- **官方协议**：来自供应商或标准的当前文档；
- **研究结论**：来自论文特定设置下的实验；
- **解释或推断**：作者为了帮助理解而做的类比与归纳。

看到“因此”“意味着”时尤其要留意：后面常常是解释，而不是源码原句。

### 阅读后：画最小图

只画当前章节必要的节点。例如工具调用只需要用户、宿主、模型、工具四个参与者。节点越多并不代表理解越深。

### 隔一天：不用原文复述

试着向一个只会调用 API 的同学解释。如果必须连续使用三个没有定义的热词，说明中间还有概念缺口。

## 遇到版本差异怎么办

先确认你打开的是文章固定的 commit 链接，还是 Pi 最新 `main`。如果固定版本能对上、最新版本对不上，这通常是上游演进，不一定是你理解错误。处理方法见[源码版本为什么重要](03-source-version.md)。

## 给仓库作者的使用建议

如果你也在参与写作，不必强迫每章拥有相同结构。概念章节可以从生活化例子开始，API 章节适合表格，源码章节适合调用链，论文条目则应说明它与 Pi 的哪一个问题相关。共同底线是：可查证、标版本、少夸大、能让初学者继续往下走。

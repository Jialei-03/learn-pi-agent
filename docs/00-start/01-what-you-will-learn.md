# 你将学到什么

学习一个 Agent 项目，最容易获得的是一串类名，最难获得的是一套可以迁移的理解方式。本仓库的目标不是让你背下 Pi 当前版本的文件结构，而是让你在面对 Pi、其他 Agent 项目甚至未来的新协议时，仍然知道应该问哪些问题、从哪里验证答案。

## 先说结论：你会形成五项核心能力

### 1. 区分模型、Agent 与宿主程序

你会理解普通模型调用通常只是“输入消息，得到消息”，而 Agent 是宿主程序围绕模型组织的一段持续过程。模型可以表达“我想调用天气工具”，真正读取网络、运行命令或修改文件的是拥有这些权限的宿主程序。

学完基础部分后，你应该能够解释：

- 为什么换一个更强的模型，不会自动得到文件系统权限；
- 为什么 tool call 是结构化的动作请求，而不是动作本身；
- 为什么 Agent 的可靠性同时取决于模型、工具实现、循环控制和安全边界。

### 2. 读懂一次 Agent 对话中的消息与事件

你会认识 `user`、`assistant`、`tool call`、`tool result`，也会理解流式输出不是“模型一句一句思考”，而是服务端把内容与事件增量送回客户端的一种传输方式。

当看到 OpenAI、Anthropic 或 Pi 的不同类型时，你不会只比较字段名，而会先找出它们共同表达的语义：

1. 用户提出目标；
2. 模型返回文本或工具请求；
3. 宿主执行工具；
4. 工具结果作为新消息回到上下文；
5. 模型基于新信息继续生成。

### 3. 画出 Pi 的三层主结构并说明职责

你会逐步认识三个最重要的包：

- `pi-ai`：统一不同模型提供商的消息、模型、流式事件和工具调用；
- `pi-agent-core`：围绕模型运行 Agent 状态、事件和工具循环；
- `pi-coding-agent`：把会话、编码工具、资源、扩展与交互体验装配成 coding agent。

目标不是背这三句话，而是能够解释为什么这种分层能让“接入模型”“运行通用循环”和“处理编码场景”相对独立。

### 4. 沿真实调用链寻找答案

你会练习沿下面的主线阅读，而不是在仓库里随机点文件：

```text
AgentSession
    ↓ 装配并发起一轮交互
Agent / AgentHarness
    ↓ 管理状态与事件
runAgentLoop
    ↓ 组织模型消息与工具结果
pi-ai provider
    ↓ 转换为具体厂商 API
OpenAI / Anthropic / 其他模型服务
```

随着章节展开，你应该能回答：输入在哪里进入？状态由谁持有？工具请求在哪一层被执行？流式事件怎样回到界面？如果上游重构了文件名，应该根据哪些类型和函数重新找到路径？

### 5. 理解长会话为什么需要树与压缩

“记忆”在 Agent 文章里经常被说得很模糊。你会明确区分：

- 模型训练后参数中已有的知识；
- 磁盘上保存的完整会话记录；
- 本轮真正发给模型的有限上下文；
- 为节省 token 而生成的摘要或压缩结果。

在此基础上，你会理解 Session 树怎样支持恢复与分支，compaction 怎样缓解上下文窗口压力，以及摘要为什么也可能丢失关键细节。

## 你还会学会一种阅读方法

本仓库会反复使用四层验证：

| 层次 | 要问的问题 | 主要证据 |
| --- | --- | --- |
| 直觉 | 它解决了什么可感知的问题？ | 小例子、反例、流程图 |
| 协议 | 行业 API 怎样表达这件事？ | OpenAI、Anthropic、MCP 官方文档 |
| 研究 | 这个思路从哪里来，有什么边界？ | 论文原文与实验结论 |
| 工程 | Pi 具体怎样实现？ | 固定 commit 的源码、类型和运行路径 |

这样做的好处是：概念不会悬在空中，源码也不会退化成逐行翻译。

## 学完不等于什么

读完本仓库并不保证你能够从零重写完整的 Pi，也不保证你已经掌握生产级 Agent 的安全、评测、成本与运维。Pi 是持续演进的真实项目，理解它需要反复运行、查证和修正心智模型。

更现实的完成标准是：

- 你能用自己的话解释关键概念，不依赖热词；
- 你能用官方文档核对 API，而不是复制过时的博客代码；
- 你能在固定版本源码中找到证据；
- 你知道哪些结论是事实，哪些只是设计权衡或合理推断。

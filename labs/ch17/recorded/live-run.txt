## 位置
mox 就是本仓库的 agent（`mox/`），压缩实现集中在 **`mox/src/compaction.ts`**，会话投影在 **`mox/src/session.ts`**，触发接线在 **`mox/src/cli.ts`**。

## 触发条件
`mox/src/compaction.ts:10-12`
```ts
return contextTokens > contextWindow - reserveTokens;
```
- `reserveTokens` = 16384（`compaction.ts:7`），`contextWindow` = `MOX_CONTEXT_WINDOW` 默认 128000（`cli.ts:88`）→ 实际触发线约 **111616 tokens**
- 纯 token 数触发，无消息条数阈值、无占比
- 三个触发点：`cli.ts:105`（用户提问前）、`cli.ts:113` → `loop.ts:72`（每轮工具执行完）、手动 `/compact`（`cli.ts:178`）
- ⚠️ mox **没有** Pi 的"撑爆后补救"路径（搜 `overflow`/`context_length_exceeded` 在 `mox/` 下零命中）

## 切分规则：按 token 从后往前累加
`mox/src/compaction.ts:29-45`
- 从最新消息往回累加 token，攒够 `keepRecentTokens`（默认 **20000**，`compaction.ts:7`）即停
- 合法切点只允许落在 **user / assistant** 消息上，**绝不切在 toolResult**（否则保留段开头是孤立结果，服务商拒绝）
- 切点不是 user 消息时标记 `isSplitTurn`，并回溯 `turnStartIndex`（那一轮的用户消息）；Pi 对 split turn 写两份摘要，**mox 简化为合并进同一份摘要**

## 切掉的部分如何替代
- **原始消息一条都不删**。JSONL 会话文件追加一条 `{type:'compaction', summary, firstKeptId, tokensBefore}` 记录（`session.ts:109`）
- 改变的是发给模型的投影（`session.ts:133-142`）：**摘要以一条 `role:'user'` 消息放在上下文最前**，用 `<summary>…</summary>` 包裹，后面接"从 `firstKeptId` 起保留的消息 + 压缩之后的消息"
- 摘要正文 = 模型生成的结构化文本 + 程序自动附加的 `<read-files>`/`<modified-files>` 清单（`compaction.ts:145-149`）
- 摘要请求前先 `serializeConversation` 转纯文本（防止模型"接着对话"），工具结果截断到 2000 字符（`compaction.ts:63`）；已有摘要则要求**合并而非重写**（`compaction.ts:111-116`）
- `reply.stopReason !== 'stop'` 直接抛错、不写入任何内容（`compaction.ts:139`）

## 可配置
`MOX_CONTEXT_WINDOW`（唯一环境变量）；`reserveTokens` / `keepRecentTokens` 是代码常量、无开关（Pi 上游有 `enabled` 字段，mox 未实现）。`/compact <要求>` 可传摘要侧重点并强制压缩。

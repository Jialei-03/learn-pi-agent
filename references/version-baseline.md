# 来源与核对方法

课程以 Pi 原始代码作为实现证据。正文中的源码链接用于定位函数和调用者；局部摘录不能替代完整函数的异常路径。教学示意与应用伪代码有明确标记。

## 维护证据

`source-evidence.json` 保存源码摘录的位置与内容摘要，供维护脚本检查。正文不反复插入版本声明。上游变化后需要重新阅读相关调用链，再更新讲解和证据，不能只替换 URL。

## 区分几类验证

- 源码核对：确认文件、类型、函数、分支与引用确实存在。
- 单元测试：在模拟或受控输入下验证运行行为。
- 集成测试：确认多个真实组件组合后的行为。
- 模型评测：用真实模型完成任务并评价产物、轨迹和成本。

阅读到测试不等于执行过测试；一次测试通过也不能替代所有外部服务和操作系统环境。当前执行记录见仓库中的 `references/verification.json`。

## 图的作用

Mox 插图解释关系和过程，是教学隐喻；精确字段、事件名称与执行顺序以正文和源码为准。新图的提示词、角色规范和资产位置保存在 `assets/mox-mechanisms/`，方便后续保持一致。
